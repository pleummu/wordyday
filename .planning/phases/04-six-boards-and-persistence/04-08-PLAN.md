## Phase Goal

**As a** player, **I want to** keep a separate saved game on each of the six Boards that survives refreshes, mode and length switches and broken storage, with a fair Give Up and a way to reset everything, **so that** I can come back to any game later without ever losing progress.

<objective>
Close CR-01 (verification gap "Saved data has a version number and a migration chain that protects data across updates"): a document from a newer app version is recognised as "newer", not "corrupt". This build then stops writing for the rest of the session, so an old tab or a rolled-back deploy can never wipe Phase 5 streaks and Restores.

Purpose: SAVE-05/SAVE-06 intent. Phase 5 bumps SAVE_VERSION to 2, and this v1 code is what will run in old tabs after that deploy, so the fix must ship in v1.
Output: `loadSave` reason field, storage read-only mode, store ignores newer external docs, unit tests for boot and storage-event paths.
</objective>

| T-04-08-02 | Denial of Service | loadSave on a hand-edited `{"version": 999999}` document | mitigate | Newer is decided only from an integer version; the game still starts fresh in memory and stays playable; no throw escapes (existing try/catch kept) |
| T-04-08-03 | Repudiation/Integrity | ':corrupt' backup slot | mitigate | 'newer' never writes the backup, so a real corrupt backup is not overwritten by a merely newer document |
| T-04-08-04 | Information disclosure | saved games | accept | Local-only data, no PII, nothing leaves the browser |
