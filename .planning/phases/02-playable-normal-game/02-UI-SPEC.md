# Phase 2 — UI Design Contract

> Visual and interaction contract for the playable Normal game. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: SPEC.md (R-GUESS-*, R-SCORE-*, R-UI-4, R-UI-8), REQUIREMENTS (PLAY-01..06, UI-01, UI-06, UI-09), CLAUDE.md (design constraints), and the Phase 1 tokens in `src/styles/tokens.css`. No CONTEXT.md or RESEARCH.md exists for this phase; all values below are defaults chosen by the researcher, not user answers. The user may override any of them.

## Scope

In scope: header (title + length picker only), game grid, tiles, on-screen keyboard, toast, answer reveal on loss, finished-game "Play again", loading and pool-load-error states, animations (pop, flip, shake), 320 px layout.

Out of scope (later phases, but tokens must extend cleanly): Mode toggle, help/stats/settings buttons (Phase 3/5/7), modals and confirm dialogs (Phase 4), result modal, share and definition (Phase 6), dark and colour-blind palettes (Phase 7), persistence and six Boards (Phase 4). In Phase 2 the game is Normal mode only; there is no mode toggle. Leave the header layout with space for icon buttons on the right so Phase 3 does not reflow it.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-written plain CSS; `components.json` not present, shadcn gate answered "N" by project constraints: no component library, no Tailwind) |
| Preset | not applicable |
| Component library | none |

| Font | `--font-body: system-ui, -apple-system, 'Segoe UI', sans-serif` (existing token). No web font, no extra network request. |

Styling approach: plain CSS with custom properties in `src/styles/tokens.css` (extend, do not replace) plus component CSS in `src/styles/`. Theme variables live on `:root` now and must be written so a later `[data-theme="dark"]` and `[data-palette="colorblind"]` block can override only the colour tokens listed under Color. Never hard-code a hex value in component CSS; always reference a token.

## Spacing Scale

Existing tokens `--space-1..4` (4, 8, 16, 32) are kept. Add the rest of the scale:

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` (xs) | 4px | Tile gap, key gap in a row, icon gaps |
| `--space-2` (sm) | 8px | Gap between keyboard rows, length-picker segment gap, toast inner padding vertical |
| `--space-3` (md) | 16px | Page horizontal padding at 320-479 px, toast inner padding horizontal, header vertical padding |
| `--space-4` (xl) | 32px | Page horizontal padding at 480 px and up, gap between grid and keyboard on tall screens |
| `--space-5` (lg) | 24px | Gap between header and grid on tall screens (new) |
| `--space-6` (2xl) | 48px | Header height, minimum vertical breathing room above grid on desktop (new) |
| `--space-7` (3xl) | 64px | Desktop top padding (new) |

Exceptions (all intentional, all documented here):

- Tile size is computed, not a token (see Layout). It is whatever fits, between 44 px and 62 px.
- Key height is 44 px (touch target) on viewports at least 640 px tall and 40 px below that. Key min-width 28 px for letter keys on 320 px screens (10 keys + 9 gaps of 4 px must fit in 288 px content width: (288 - 36) / 10 = 25.2 px, so letter keys are `flex: 1` with no min-width below 25 px). Targets under 44 px on the shortest phones are accepted: WCAG 2.5.8 AA (24 px minimum) is satisfied.
- Grid gap shrinks to 4 px (`--space-1`) always; it never uses 8 px so 6 columns fit 320 px.
- Toast offset from top: 16 px (`--space-3`).

## Typography

Exactly 4 sizes and 2 weights (400, 600).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label (keys, picker, toast, banner) | 14px | 600 | 1.2 |
| Heading (site title "Unlimited Wordle") | 20px | 600 | 1.2 |
| Display (tile letters) | 28px | 600 | 1 |

Rules:

- Tile letters are always uppercase (`text-transform: uppercase` on the display only; stored letters are lowercase or uppercase consistently as the logic chooses). Display 28 px fits a 44 px tile (28 px cap height box plus centred flex).
- Key labels use Label 14 px, uppercase letters; "Enter" is written "Enter" in Label 14 px (not uppercase) to stay readable in a 1.5-key-wide button.
- Letter spacing 0 everywhere except the title (0.01em allowed). No italics. No other sizes or weights anywhere in Phase 2.
- `font-variant-numeric: tabular-nums` on any attempt counter text.

## Color

Light theme only in Phase 2. Define every colour as a semantic token so Phase 7 overrides them per theme. Existing: `--color-bg #fbfaf7`, `--color-text #2b2d33`, `--color-muted #7a7f8a`, `--color-accent #a9c4b0`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fbfaf7` (`--color-bg`) | Page background, empty-tile fill |
| Secondary (30%) | `#f0eee8` (`--color-surface`, new) | Unused keys, length-picker track, toast surface (with `--color-text` text) |
| Accent (10%) | `#a9c4b0` (`--color-accent`, existing sage) | See reserved list below |
| Destructive | `#c97b7b` (`--color-error`, new, soft rose) | Error toast left border only, and loss answer banner border. No red fills. |

Tile / key state tokens (new). Text on all of these is `--color-text` (#2b2d33) for contrast, never white:

| Token | Value | Meaning | Contrast of #2b2d33 on it |
|-------|-------|---------|---------------------------|
| `--tile-empty-border` | `#dcd9d0` | Empty tile 2px border | n/a (decorative) |
| `--tile-filled-border` | `#a8a59c` | Tile with a typed letter, before submit (2px) | n/a |
| `--tile-correct` | `#a9c4b0` (same value as accent) | Correct (green role) | about 7:1 |
| `--tile-present` | `#f0d79a` | Present (yellow role) | about 9:1 |
| `--tile-absent` | `#cfccc3` | Absent (gray role) | about 8:1 |

Distinction note: correct, present and absent differ in hue and lightness, not hue alone. Phase 7 adds the colour-blind palette by overriding these three tokens (orange/blue per R-SHARE-2); do not rely on colour alone later, so tile `data-state` attributes (`correct`/`present`/`absent`) are mandatory and used by CSS selectors.

Key colours: unused key = `--color-surface`; key states reuse `--tile-correct|present|absent`. A key keeps its best state (R-GUESS-6) and updates only after the flip finishes.

Accent reserved for (exhaustive list):
1. Correct tiles and correct keys (as `--tile-correct`)
2. The selected segment of the length picker (fill)
3. The keyboard focus ring (`outline: 2px solid` accent darkened to `#6f9a7c` for 3:1 against the bg; token `--color-focus`)
4. The "Play again" button fill

Never use accent for: titles, text, borders on empty tiles, hover on every interactive element.

Soft shadows: allowed only on the toast (`0 4px 16px rgba(43,45,51,0.08)`) and the Play again button (`0 2px 8px rgba(43,45,51,0.06)`). No other shadows. Border radius: tiles `--radius-tile` 14px at tile size 52 px and up, 10px below that (`--radius-tile-sm`, new); keys 10px; picker segments and buttons 999px pill; toast and banner `--radius-card` 20px reduced to 14px for the toast.

## Layout and Components

### Page structure (single column, centred, max width 480 px for the game column)

```
<header>      title left, length picker centred/below on narrow, space reserved right for Phase 3 icon buttons
<main>        grid (centred), toast layer (fixed, top), finished banner (below grid)
<keyboard>    bottom, full width of the column
```

Use a flex column on `body > #root` with `min-height: 100dvh` (with `100vh` fallback declared first), `height: 100dvh` on the app shell, `overflow: hidden` is NOT used; the grid area is `flex: 1` and centres its content; the keyboard never scrolls off screen. Header is 48 px tall (`--space-6`). Page padding: 16 px at widths 320-479, 32 px at 480 and up. Desktop (min-width 768): add 64 px top padding.

### Length picker (Phase 2 scope)

- A segmented control of three buttons labelled "4", "5", "6" with a visually hidden prefix, announced as "4 letters", "5 letters", "6 letters". Container is `role="radiogroup"` with `aria-label="Word length"`; each button `role="radio"` with `aria-checked`. Arrow Left/Right moves selection; Tab enters the group once.
- Height 40 px, segment min-width 44 px, pill track `--color-surface`, selected segment filled `--color-accent` with `--color-text` text, weight 600 Label 14 px.
- Switching length in Phase 2 starts a new game at that length immediately with no confirm (persistence and Boards arrive in Phase 4). Switching is disabled (`aria-disabled`, no-op) while a reveal animation is running.
- Position: in the header row on widths 400 px and above (title left, picker right). Below 400 px the header wraps to two rows only if the title and picker do not fit (title 20 px "Unlimited Wordle" is about 168 px, picker 3 x 44 plus gaps = 140 px, total 308 px which exceeds the 288 px content width at 320). Contract: at widths under 400 px the title is centred on row 1 (height 32 px) and the picker is centred on row 2 (height 40 px). Combined header height at 320 px is 80 px (32 + 40 + 8 gap).

### Grid

- Rows = attempts (5/6/7 for 4/5/6 letters), columns = word length. `role="grid"` with rows `role="row"`, tiles `role="gridcell"`; each tile `aria-label` e.g. "Row 2, column 3, letter A, correct" or "empty" (the full aria-live announcement is Phase 7 scope, but labels are required now because they are cheap).
- Tile size is `--tile`, computed with CSS `min()`:
  `--tile: clamp(44px, min( (100% - (cols - 1) * 4px) / cols, (available-height - (rows - 1) * 4px) / rows ), 62px)`. Implementation may use a container-query-units or a small JS resize measure; the contract is the outcome: tiles are square, 44-62 px, gap 4 px, and the whole grid never exceeds its available area.
- Fit proof for the worst case (6 letters x 7 rows, iPhone SE 320 x 568): content width 288 px gives (288 - 20) / 6 = 44.6 px tile, so 44 px. Grid height = 7 x 44 + 6 x 4 = 332 px. Budget: header 80 + gap 8 + grid 332 + gap 8 + keyboard (3 x 40 + 2 x 8 = 136) = 564 px of 568 px. Allowed vertical padding is therefore 2 px; page vertical padding is 0 below 600 px viewport height and keyboard key height is 40 px below 640 px height. If the available height is still less than needed, tile size may drop to 40 px as a last-resort floor only when `height < 568px`, to avoid scroll. Verify at 320 x 568 and 320 x 640 in Playwright/visual check.
- Empty tile: `--color-bg` fill, 2 px `--tile-empty-border`. Typed (pre-submit): 2 px `--tile-filled-border`. Submitted: filled with state colour, border 2 px same as fill.
- Active row is the first row without a submitted guess. Only that row accepts typing and shakes.

### On-screen keyboard

- Three rows, QWERTY: `Q W E R T Y U I O P` / `A S D F G H J K L` (row 2 indented by half a key using 0.5 flex spacers) / `Enter` + `Z X C V B N M` + `Backspace`. Enter and Backspace are `flex: 1.5`.
- Each key is a `<button type="button">`, `aria-label` equals the letter (or "Enter", "Backspace"); key state is conveyed in the label too: `"A, correct"`, `"B, absent"`.
- Key radius 10 px, no border, `--color-surface` fill, press feedback: `transform: scale(0.96)` for 80 ms (removed under reduced motion; replaced by a background shift to `#e6e3da`).
- Physical keyboard: letters append, Backspace deletes, Enter submits; `keydown` listener ignores events with Ctrl/Meta/Alt held and ignores key repeat for Enter. Input is ignored while a reveal runs, when the game is finished, and while the pool is loading.
- Keys do not take focus on tap in a way that shows a focus ring on touch (use `:focus-visible` only).

### Toast

- One toast at a time, fixed top centre, 16 px below the safe-area top (`env(safe-area-inset-top)`), max width 288 px at 320 px (`calc(100vw - 32px)` max 360 px). Surface `--color-surface`, 14 px Label text, 1 px border `--color-error` for errors, radius 14 px.
- Appears with an opacity-and-8px-translate fade (160 ms), stays 1500 ms, fades out (200 ms). A new toast replaces the current one instantly. `role="status"` / `aria-live="polite"`; error toasts use `role="alert"`.
- Used for: too short, not in word list, and (Phase 2) win praise. Never blocks input.

### Finished state

- Win: the winning row finishes its flip, then a tiny bounce of the row (see Animations) and a toast with praise. Below the grid, a banner appears.
- Loss: after the last flip, the banner shows the answer. The answer is shown in uppercase in 20 px weight 600 inside the banner, never inside the grid.
- Banner: `--color-surface` fill, radius `--radius-card`, 16 px padding, centred text; loss banner has a 1 px `--color-error` border. Contains the message and a "Play again" button (pill, accent fill, `--color-text` text, Label 14 px, height 44 px, min-width 128 px). The keyboard is replaced by the banner when the game finishes (see decision below), so nothing is dimmed or overlaid.
  **Decision for the executor: unmount the keyboard when the game is finished and render the banner in its slot (same height, 136 px minimum), so the layout never jumps and fits 320 x 568.**
- Focus: after a game finishes, move focus to the "Play again" button. After pressing it, move focus to the page body (physical keyboard resumes working).

### Loading and error states

- Word pools load per length on demand (lazy chunk). While loading, show an empty grid of the right size (normal empty tiles) and the keyboard disabled; no spinner. Typed letters are accepted into the active row only after load completes (ignore input before). If load takes over 400 ms, show the text "Loading words..." (Body 16 px, `--color-muted`) in the toast position.
- Load failure: replace the keyboard slot with a banner: "Couldn't load the word list. Check your connection and try again." and a "Try again" button (same style as Play again). Grid stays visible.

## Animations

All via CSS `@keyframes` and `animation-delay`; re-trigger by toggling a class or changing a `key`. Easing: `cubic-bezier(0.3, 0.7, 0.4, 1)` for pop and flip, `ease-in-out` for shake. No spring libraries, no JS animation.

| Animation | Trigger | Duration | Detail |
|-----------|---------|----------|--------|
| Pop | A letter is typed into a tile | 100 ms | scale 1 to 1.08 to 1 on that tile; border switches to `--tile-filled-border` |
| Flip | A valid guess is submitted, per tile | 500 ms each, stagger 300 ms (`animation-delay: calc(var(--i) * 300ms)`) | rotateX 0 to 90deg (tile face empty), swap to state colour at 50% (250 ms), rotateX 90 to 0 deg. State colour is applied at the midpoint via keyframes, not before. |
| Shake | Invalid or too-short guess | 400 ms | The active row translates X: 0, -6px, 6px, -4px, 4px, 0; the toast shows at the same time. No attempt is used. |
| Win bounce | After the last flip of a winning row | 400 ms, tile stagger 100 ms | translateY 0, -12px, 0 per tile; Skipped under reduced motion. |
| Toast | Show/hide | 160 ms in, 200 ms out | opacity and 8px translateY |
| Key colour | After the row's flip finishes | 160 ms | background-color transition to state colour. Fires when the reveal completes: `(cols - 1) * 300 + 500` ms after submit (1100 / 1400 / 1700 ms for 4 / 5 / 6 letters). |

Timing contract:

- Total reveal time = `(cols - 1) * 300 + 500` ms (1100 ms at 4 letters, 1400 ms at 5, 1700 ms at 6). Input is blocked for exactly this duration plus a 50 ms buffer; implemented with `animationend` on the last tile, with a `setTimeout` fallback.
- Key colours and the finished banner appear only after the reveal completes.

Reduced motion (`@media (prefers-reduced-motion: reduce)`, and the same query read in JS for timing):

- Pop, flip, shake, win bounce and key press scale are disabled (no transform animations).
- Reveal: each tile swaps to its state colour with a 120 ms opacity cross-fade, stagger 0 ms; total reveal delay 150 ms. Input is blocked for 150 ms. Key colours update right after.
- Shake is replaced by a 2 px `--color-error` outline on the active row for 800 ms, plus the toast. Toast uses opacity only (no translate).
- The state change is always visible and colour is applied; nothing is hidden by the missing animation.

## Interaction Rules

- Letter keys fill the active row left to right up to the length; further letters are ignored.
- Backspace removes the last typed letter; no-op when empty.
- Enter with fewer letters than the length: shake plus toast "Not enough letters" (no attempt used).
- Enter with a full row not in the Guess Pool: shake plus toast "Not in word list" (no attempt used).
- Enter with a valid word: start the reveal, block input, score using the pure scoring module, then update keys, then check win/loss.
- Win on any row: praise toast keyed by attempt number (see Copywriting), then banner. Loss on the last row: banner with the answer. Both unmount the keyboard.
- Play again: draws a new random answer for the same length (repeats allowed), clears the grid, restores the keyboard, focus returns to the page.
- Length change mid-game: abandons the game silently (Phase 2 only; Phase 4 replaces this with saved Boards). Note for the planner: this is a temporary behaviour and must not touch any stats.

## Accessibility (Phase 2 minimum; full pass in Phase 7)

- All interactive elements reachable by Tab in this order: length picker, keyboard keys (roving or sequential), Play again button when present. Visible `:focus-visible` ring: 2 px `--color-focus` with 2 px offset.
- Touch targets: length picker segments 44 x 40, keys 40-44 px high, Play again 44 px high.
- Colour contrast: body text 4.5:1 or better on all surfaces, tile letters 4.5:1 or better on all three state fills (values listed under Color).
- Tile labels and key labels include state (see Layout). The aria-live announcement region for guess results is added in Phase 7; Phase 2 only has the toast `role="status"` and the grid labels.
- `lang="en"` on `<html>`. Zoom is not disabled (no `user-scalable=no`).
