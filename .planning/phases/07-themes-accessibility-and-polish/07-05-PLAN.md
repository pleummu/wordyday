<objective>
User story slice: **As a** screen-reader player, **I want** to hear each guess's letter-by-letter result once the tiles finish flipping, and a short line when the game ends, **so that** I can play without seeing the colours.

Give Up and modal inertness (checker revision 1): giveUp() sets the line and opens the Result dialog in one synchronous step, and showModal() makes everything outside the dialog inert, so a plain region outside it may never be spoken. Routing Give Up through scheduleResult would add a pause that Phase 6 locked out ("Right after a confirmed Give Up the Result modal opens with no extra pause", 06-01, D-02). The smallest robust fix that keeps that decision is the pattern this codebase already uses to announce toasts above the Result modal (06-04): the live region is a popover="manual" element, always mounted and shown, and re-raised into the top layer above each newly opened dialog, so it is never part of the inert page. Final proof is the NVDA Give Up step in 07-08.

Purpose: UI-07 (D-10..D-13). Tile and key labels already exist (Tile.tsx, Keyboard.tsx); this plan adds the live region and guards the labels with the E2E.
Output: failing announce.spec, pure announce.ts (TDD), store announcement, LiveRegion in App.
</objective>
