# Phase 7 — UI Design Contract

> Visual and interaction contract for the dark theme, colour-blind palette, Appearance settings, How-to-play modal, header help button, screen-reader live region, keyboard audit and link-preview assets. Extends `02..06-UI-SPEC.md` (spacing, typography, motion, `Modal`, buttons, tiles all still apply); only deltas are specified. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
> Sources: 07-CONTEXT.md D-01..D-19 (locked), 07-RESEARCH.md, current `src/styles/tokens.css`, 06-UI-SPEC.md.
> Marking: `[LOCKED]` = fixed by SPEC/CONTEXT. `[DISCRETION]` = Claude's choice. Hex values marked `[TUNE]` are starting points measured by script (WCAG ratios below); the executor must adjust the minimum amount needed to pass axe and keep the stated ratios.

## Scope

In scope: `[data-theme='dark']` and `[data-palette='colour-blind']` token sets (all four combinations); Appearance section in Settings; How-to-play modal; "?" header button; visually hidden live region; focus-ring checks in every theme/palette; `index.html` metadata, noscript, favicon, apple-touch-icon, OG image.

Out of scope: any change to layout, tile geometry, typography scale, spacing scale, animations (reduced motion already done), Share text (stays ⬜ for absent in every theme `[DISCRETION]`), skip link (declined).

## Spacing Scale

Unchanged tokens (`--space-1..7` = 4, 8, 16, 32, 24, 48, 64). No new tokens.

| Token | Phase 7 usage |
|-------|---------------|
| `--space-1` (4px) | Gap between header action buttons; gap between hint text and its control label |
| `--space-2` (8px) | Gap between example tiles and its caption; gap between the three theme segments; gap between Appearance rows |
| `--space-3` (16px) | Gap between How-to-play sections; Appearance section bottom padding before the divider; modal card gap (existing) |
| `--space-5` (24px) | Modal padding (existing; 16px at `max-height: 540px`) |

Exceptions (component sizes, not spacing tokens):
- Header help button: 36px square below 400px, 40px at >= 400px, identical to the Stats and Settings buttons (reuse their rules by adding `.help-button` to the same selector lists, including the short-viewport block). - How-to-play example tiles: 36 x 36px, gap 4px, radius `--radius-tile-sm` (10px), letter 20px/600 (the Heading size, not the 28px tile Display size, so a 5-tile example row of 36px tiles + 4 gaps = 196px fits the 296px content width at 320px).

### Colour-blind palette `[LOCKED: colours only, no markers/patterns]` (D-03)

Only `--tile-correct` and `--tile-present` change (keys use the same tokens). Absent grey is unchanged per theme. Tile/key label text stays `--color-text`. Orange vs blue are separated by hue and saturation; their luminances are deliberately not equal-and-low, so orange is the warmer/more saturated, blue the cooler.

| Combination | `--tile-correct` (orange) | `--tile-present` (blue) | Text on each |
|-------------|--------------------------|-------------------------|--------------|
| Light + colour-blind | `#e8913a` `[TUNE]` | `#6aa5e3` `[TUNE]` | `#2b2d33` on orange 5.6:1, on blue 5.3:1 |
| Dark + colour-blind | `#9a5212` `[TUNE]` | `#1c4f8c` `[TUNE]` | `#ece9e2` on orange 4.8:1, on blue 6.8:1 |

Selector order in `tokens.css` (later wins): `:root` then `[data-mode='wordubado']` then `:root[data-theme='dark']` then `:root[data-palette='colour-blind']` then `:root[data-theme='dark'][data-palette='colour-blind']`. `--color-mode` on `.app` keeps working because dark only redefines `--color-wordubado`.

Colour-blind palette must be distinguishable by hue with correct/present/absent all visible side by side; verify by screenshot of a mixed row in all four combinations before sign-off.

### Accent (sage) reserved list after Phase 7 (exhaustive; extends Phase 6)

Correct tiles/keys (except under colour-blind where orange replaces it), selected length segment, **selected theme segment**, **colour-blind switch when on**, Play again fill, dialog primary buttons, selected Stats length tab, highlighted distribution bar, win-heading accent bar, the favicon tile. Focus ring uses `--color-focus`. Not accent: help button, Close buttons, the "?" icon, example row captions.

When colour-blind is on, accent-coloured selected states (segments, switch) stay sage; they are not game-state colours.

## Layout and Components

### Header help button (D-06) `[LOCKED]`

`<button class="help-button" aria-label="How to play">` with the "?" SVG, first child of `.header-actions` (order: Help, Stats, Settings). Same size, radius, fill (`--color-surface`), hover, `:focus-visible` ring (`2px solid var(--color-focus)`, offset 2px) as Stats/Settings. Disabled and hidden states follow Stats (disabled while input is blocked by reveal or pending prompt; use the same guard as `openSettings`). Fits at 320px two-row header (see Spacing exceptions).

### Settings modal: Appearance section (D-04) `[LOCKED position]`

Top of the Settings modal card, above the browser-only note and "Reset my data", followed by a 1px `--tile-empty-border` divider.

```
Appearance                               <- Label h3 (.modal-subheading)
Theme
[ System ][ Light ][ Dark ]              <- segmented radiogroup, 44px
Colour-blind friendly colours   (o)--    <- switch row, 44px
Orange and blue instead of green and yellow   <- hint, Label-regular
-------------------------------------------
(existing browser-only note, Reset my data)
```

| Part | Spec |
|------|------|
| Theme control | `role="radiogroup"` `aria-labelledby` the "Theme" label; three `<button role="radio" aria-checked>`; roving `tabindex` (selected = 0), ArrowLeft/Right (and Up/Down) move and select, Home/End jump; copy the `LengthPicker` markup and `.length-picker` visuals (track `--color-surface`, selected segment `--color-accent` fill with `--color-text`, pill radius). `[DISCRETION]` |
| Colour-blind switch | `<button role="switch" aria-checked aria-describedby=hint>`; copy the `ModeSwitch` visuals; label left, switch right; on = sage track |
| Buttons only | Never native `input` radio/checkbox: `Modal`'s Tab trap only collects `button, textarea` |
| Live apply | Changes apply immediately (no Save button), the board repaints behind the dialog; nothing is announced beyond the control's own `aria-checked` change |
| Reset | "Reset my data" also resets theme to System and colour-blind to off (D-04); its confirm copy must say so (see Copywriting) |
| Initial focus | Unchanged (Close button keeps `data-initial-focus`) |

### How-to-play modal (D-05, D-07..D-09) `[LOCKED content]`

Built on the shared `Modal` (`dialog` name `help`; dismissable via Esc, backdrop click and a Close/"Got it" button). Card `min(360px, calc(100vw - 32px))`, padding 24px, gap 16px; same `max-height: calc(100dvh - 32px)` with inner scroll as Stats/Result. At `max-height: 540px` padding 16px, gap 8px. Page itself never scrolls.

```
How to play                         <- Heading h2
Guess the word in as few tries as you can. Every guess must be a real word.
(example 1)  [C][R][A][N][E]  C is in the word and in the right spot.   <- example rows
...
Pick 4, 5 or 6 letters. Normal uses everyday words; Wordubado uses slang.
Win Streak counts wins in a row on each length. Day Streak counts days you play; Restores can save a missed day.
[        Got it        ]            <- primary, data-initial-focus
```

| Part | Spec |
|------|------|
| Rules line | Body 16/400. Copy is length-neutral (no "6 tries"), since tries differ per length. |
| Example rows | Three rows, each a `<div role="img" aria-label="{sentence}">` (not `role="grid"`; avoids nested live grids and axe `aria-required-children`). Each shows one 5-letter word with exactly one tile in the demonstrated state, others absent-neutral (`--tile-empty-border` outline, no fill). Tiles reuse `.tile` classes with `data-state="correct|present|absent"` so they follow theme and palette automatically. Caption beside/below (Label-regular 14/400, with the state word in Label 14/600). Example words and captions: see Copywriting |
| Layout of an example | Tiles row (196px) on top, caption below at `--space-2`; stacked so nothing wraps at 320px |
| Closing | "Got it" closes (primary, 44px, full width); Esc/backdrop also close |
| Focus | Opens with focus on "Got it"; on close, focus returns to the opener (help button) via `Modal` `fallbackFocus = .help-button`; on auto-open (opener is body) it lands on the help button as fallback |
| Auto-open (D-07..D-09) | First visit and once for existing players after the v2 to v3 migration: opens on load unless a Restore prompt, streak-break modal, Wordubado popup, another dialog or a reveal is active; then it opens right after that blocker clears and never stacks on it. Seen flag set the moment it opens |
| Animation | Existing `modal-in` 160ms / `modal-out` 120ms; reduced motion uses the existing fade. No flourish |

Vertical budget at 320 x 500: heading 24 + rules 48 + 3 examples x (36 + 8 + 21 = 65) = 195 + modes line 42 + streak line 63 + button 44 + 6 gaps x 8 + padding 32 = about 496, which exceeds the 468 dialog max-height; the card scrolls inside the dialog (never the page), and "Got it" has initial focus so is visible on open via focus scroll. Keep copy as short as given to stay near this.

### Live region (D-10..D-13) `[LOCKED behaviour]`

One always-mounted element in `App`: `<div class="visually-hidden" role="status" aria-live="polite" aria-atomic="true">`. No visual footprint, no layout effect. Text set only at `finishReveal` (and Give Up), never on typing, backspace or board/mode switches. Visually-hidden class: 1px clip pattern, not `display:none`. Texts in Copywriting. Win/loss/Give Up lines are appended to the guess line in a single update; they are not repeated by the Result modal's heading or the Toast (each fact announced once; the praise toast stays as is).

### Focus rings (D-14)

One rule everywhere: `:focus-visible { outline: 2px solid var(--color-focus); outline-offset: 2px }`. Verify visible on: tiles-free board (keys, header buttons, Switch/Picker buttons, segments, modal buttons, textarea) in light, dark, colour-blind light and colour-blind dark. `--color-focus` dark `#8fbf9c` is >= 3:1 on bg and on surface; on sage-filled selected segments the ring sits outside the fill so contrast is against the surrounding surface.

### No-flash theme (D-01)

A classic inline `<script>` in `<head>` before the stylesheet sets `data-theme` (`light` or `dark`, resolved) and `data-palette="colour-blind"` on `<html>` and the `theme-color` meta, reading the existing versioned save doc inside try/catch. System follows `prefers-color-scheme` live (listener only while theme is System). `html` background uses `--color-bg` so the first paint is correct. No transition on theme change `[DISCRETION]`: colours swap instantly (a fade is avoided to prevent a mid-switch contrast dip; this also needs no reduced-motion branch).

## Interaction Rules

- Order of auto dialogs (D-09): Restore prompt / streak-break modal win; then How-to-play; the Wordubado popup is never auto-opened on load, only on first switch. How-to-play never opens during `revealing` or `resultPending`.
- Help button while a blocking prompt is pending is disabled with the existing disabled styling.
- Keyboard-only audit (D-14): tab order is DOM order: header (Help, Stats, Settings), length picker, mode switch, board controls, keyboard keys, banner buttons. Every dialog traps Tab, closes on Esc, and returns focus to its opener (Restore prompt excepted: not Esc-dismissable). No skip link.
- Reduced motion: unchanged; no new animation introduced in this phase.

## Accessibility (additions)

- Axe (`expectNoA11yViolations`) in light, dark, colour-blind light and colour-blind dark, each with: the game board containing a row with all three states, Settings open, How-to-play open, the Result modal open, and a toast visible.
