<objective>
User story slice: **As a** player, **I want** to choose Light, Dark or System and turn on colour-blind friendly colours in Settings, **so that** the game looks right for my eyes and stays that way next time.

Control style (Claude's discretion, decided per UI-SPEC): Theme = segmented radiogroup reusing the LengthPicker markup and .length-picker visuals; colour-blind = role=switch button reusing the ModeSwitch visuals. Buttons only, because Modal's Tab trap only collects button and textarea.

Two-tab sync (Claude's discretion, decided): applyExternal adopts the incoming doc's theme and colourBlind (a storage event only fires for the other tab's newer write), sets changedForMe when they differ and never behindThem, so the existing no-ping-pong guard still holds. startAppearance's subscription (07-04) repaints; no new listener in sync.ts.

Purpose: UI-02 (pinned choice, D-01, D-04) and UI-03 (D-03).
Output: failing E2E, store actions + two-tab adoption + palette tokens, Appearance UI + copy + reset text.
</objective>
