# Phase 5 — UI Design Contract

> Visual and interaction contract for Stats, Streaks and Restore. Extends `04-UI-SPEC.md`, `03-UI-SPEC.md` and `02-UI-SPEC.md` (tokens, typography, spacing, motion, accessibility, `Modal` all still apply); only deltas are specified here. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
> Sources: 05-CONTEXT.md D-01..D-20, SPEC.md R-RESTORE-12/13 and R-STAT, current `src/styles/tokens.css`, `game.css`, `Modal.tsx`, `Header.tsx`, `Banner.tsx`, `SettingsButton.tsx`, `Toast.tsx`.
> Marking: `[LOCKED]` = fixed by SPEC or CONTEXT. `[DISCRETION]` = Claude's choice (CONTEXT left it open); the checker/owner may override. Everything else follows Phase 4 unchanged.

## Scope

In scope: Stats button and Day Streak chip in the header, Stats modal (mode toggle, length tabs, stat row, distribution chart, footer, empty state), blocking Restore prompt, "streak ended" modal, Day Streak / Restore toasts, Win Streak line in the result banner, the non-dismissable `Modal` option, and the header fit at 320 px with three action items.

Out of scope: full result screen, definitions, Share (Phase 6); themes, colour-blind palette, how-to-play (Phase 7). Tile, key, grid, switch, length picker and forfeit row styling are unchanged.

Unchanged tokens (`--space-1..7` = 4, 8, 16, 32, 24, 48, 64). New usages:

|-------|------------------|
| `--space-1` (4px) | Gap between chip icon and count; gap between header action buttons; gap between distribution rows; gap between segments inside toggle and tabs |
| `--space-2` (8px) | Gap between stat cells' number and label; gap between "Gave up" line and chart; padding inside the mode toggle track; Day Streak chip horizontal padding |

Exceptions (intentional, each a component size not a spacing token):

- Day Streak chip and Stats button: visual height 32 px; hit area 36 x 36 minimum below 400 px, 40 x 40 at 400 px and wider (44 x 44 is not used because three items must share the title row; 36 px exceeds the WCAG 2.5.8 24 px minimum; Settings button follows the same sizes in this phase so the three are uniform). - Segmented toggle and tabs height 36 px (matches the length picker on short screens; hit area is the full 36 px; 24 px minimum met).
- Banner streak line adds one 14/600 line (about 17 px). Compensated in the banner (see Banner).

## Layout and Components

### Header actions (D-06, D-08, D-09)

DOM order inside `.header-actions` (also tab order, after the title and before the mode switch): **Day Streak chip (only when Day Streak > 0), Stats button, Settings button.** Icons left to right: `[sun 5] [bars] [sliders]`. Gap `--space-1`.

- **Stats button**: `<button type="button" class="stats-button" aria-label="Statistics" aria-haspopup="dialog" data-own-enter>`; same box, hover, active and focus rules as `.settings-button`; icon colour `--color-text`. Enabled while `revealing`. Opens the Stats modal on the current Board.
- **Day Streak chip**: `<button type="button" class="streak-chip" aria-haspopup="dialog" data-own-enter>`, pill (`--radius-pill`), height 32, padding `0 var(--space-2)` (8 px), min-width 36. Rendered only when `dayStreak.current > 0`; unmounted otherwise (no placeholder, no reserved space). While the Restore prompt is pending the chip shows the pre-break value or is hidden per the state machine; the prompt is blocking, so the chip is `inert` with the rest of the app.
- **Chip accessible name** (D-09): credited today: "Day streak {n}, open statistics". Not credited yet: "Day streak {n}, play today to keep it, open statistics". Singular "Day streak 1" needs no change (a count, not a noun phrase).
- **Count display**: show the integer as is. No abbreviation or "99+" (layout budget above covers 4 digits).

### Empty state (D-05)

When the selected tab has Played = 0:

- Stat cells: Played shows `0`; Win % shows `—`; Streak and Best show `0`; "Gave up: 0".
- The chart region is replaced by one Body 16/400 line, centred: **"No wins yet. Go play one!"**. No bars, no chart heading numerals. `Avg guesses: —` is still shown.
- Win % and Avg guesses never render `0%`, `NaN`, `Infinity` or a bare `%`. A tab with games played but zero wins shows Win % `0%` (a real value), the empty-chart line above (no wins to chart), and `Avg guesses: —`.
- Day Streak footer uses the real global values.

### Restore prompt (D-13, D-14, R-RESTORE-12/13) `[LOCKED text]`

A `Modal` (`dialog` name `restore`), not dismissable.

| Part | Copy / style |
|------|--------------|
| Heading `[DISCRETION]` (needed for `aria-labelledby`) | Streak broke |
| Body `[LOCKED]` | Your {streak}-day streak broke. Restore it? ({restoresLeft} left this month) |
| Secondary | No |
| Primary (sage, initial focus) | Restore |

- Body renders `{streak}` and `{restoresLeft}` as plain numbers; "(1 left this month)" is not pluralised because the text is locked verbatim.
- Button DOM order: "No" then "Restore". Desktop: right aligned, side by side. Below 400 px stacked `column-reverse` so "Restore" is on top (existing rule). Initial focus: "Restore". `[DISCRETION]` This departs from the "safe button first" rule because neither choice is destructive of data the player owns; Restore is the expected action and the one that continues the streak.
- **Non-dismissable**: `Modal` gets a new prop `dismissible?: boolean` (default `true`). When `false`: Esc (`cancel` event) is prevented and does nothing; backdrop click does nothing; the native `close` event while the prop is still `true` re-opens it (`showModal()` again) instead of calling `onClose`. No close icon. Only the two buttons resolve it.
- The game loads and renders normally behind the dimmed backdrop (the existing 32% scrim), inputs blocked (`isInputBlocked`, background `inert`). The prompt wins over any other dialog or open Settings/Stats (they close first); the Wordubado popup is deferred until the prompt is answered.
- If another tab answers the prompt, this tab closes it without a toast, silently applying the new state.
- After "Restore": modal closes (120 ms close), toast "Streak restored. {n} left this month." If the finish credit was deferred (EC-40) the Day Streak toast is also due; the Restore toast is shown and the Day Streak toast replaces nothing: only one toast shows at a time (Phase 2 rule), so show the Restore toast first and queue nothing; the +1 appears in the chip. `[DISCRETION]`
- After "No": modal closes, no toast, no break modal (D-16). Streak resets silently; chip disappears or shows the new value.
- Focus after either answer returns to the page body (physical keyboard resumes), like Play again.

## Interaction Rules

- **Opening Stats**: header Stats button or Day Streak chip. Both open the same modal. One dialog at a time (Phase 3 rule). Opening Stats does not touch the game and is allowed while `revealing` (it only reads saved results; the result of the game being revealed is already counted when the reveal ends, so the view must not show a half-counted game: the finish is recorded when the reveal completes, as today's `onGameFinished`).
- **Tab/radio keyboard**: Left/Right arrows move between tabs and between mode segments; Home/End jump to first/last tab; Tab moves between the toggle, the tablist, then Close. Esc and scrim close Stats; focus returns to whichever header button opened it (chip or Stats button; if the chip unmounted, fall back to the Stats button).
- **Missed-day check** runs on open, on `visibilitychange` (visible) / focus, and at the next local midnight. If it triggers a Restore prompt or streak-ended modal while the player is mid-game, the dialog appears immediately over the board (input blocked); typed letters stay in place.
- **Chip dimming** updates when the credit happens (no animation, instant) and when midnight passes (the chip dims again).
- **Reset all data** (Phase 4 flow) now also clears streaks, Restores, stats and the break marker; the chip unmounts; no new copy (existing "All data reset" toast).
- **Two tabs**: a finish counted in one tab is never counted again in the other (D-20); the other tab's Stats modal, chip and footer update from the merged document without a toast. Answering the Restore prompt in one tab closes it in the other silently.
- **Prompt in a restored state**: if the saved document holds `pendingRestore`, the prompt shows on load before any input is accepted.
- **Migration** v1 to v2 is silent: no toast and no dialog. All streaks and stats start at 0, so the first-ever Stats view is the empty state on every tab, and the chip is hidden.

## Animations and Reduced Motion

- New elements add no new keyframes: the chip, Stats button, tabs, toggle, bars and banner line mount without animation. No bar-grow animation (a deliberate choice for simplicity and for reduced motion).
- The mode toggle and tab selection change instantly (no sliding indicator).
- Dialogs (Stats, Restore prompt, streak-ended): the Phase 3/4 behaviour (160 ms scale + fade in, 120 ms fade out; reduced motion: 120 ms opacity in, instant out).
- Toasts: unchanged, including the reduced-motion opacity-only variant.
- Reduced motion: nothing new needs an override. The reveal delay before a Day Streak toast uses the existing reveal timing (the toast fires when the reveal ends, so a reduced-motion player gets it sooner automatically).

## Accessibility (additions)

- **Stats button**: `aria-label="Statistics"`, `aria-haspopup="dialog"`, `data-own-enter`.
- **Day Streak chip**: native button; name "Day streak {n}, open statistics" (or with "play today to keep it"); dimming is also in the name, never colour-only; `data-own-enter` so Enter opens Stats and never submits a guess.
- **Stats modal**: `aria-labelledby` the heading; toggle is a `radiogroup`, length selector is a `tablist`/`tabpanel` with roving tabindex and arrow-key support; the chart is a list whose items state their meaning in text (not conveyed by bar length or colour alone); highlight carried by text ", latest win"; the empty-state line is plain text in the panel.
- **Restore prompt**: a real `dialog` with `aria-labelledby` (heading) and `aria-describedby` (the locked body) so the full sentence is announced on open; focus lands on "Restore"; Esc and scrim intentionally do nothing; this is the only non-dismissable dialog, and the two buttons are the only way out (R-RESTORE-12), so there is no keyboard trap beyond the intended one.
- **Streak-ended modal**: same dialog semantics, focus on OK.
- **Toasts**: `role="status"` polite; no `alert`.
- **Banner streak line**: inside the existing polite live region.
- **Contrast**: chip count `--color-text` on `--color-bg` about 13:1; chip dimmed icon `--color-muted` about 3.8:1 (non-text 3:1 met); selected Wordubado toggle text `#7a5fb0` on `#fbfaf7` about 5:1; bar text 8 to 9:1; labels `--color-text`. Run axe with Stats open on each tab, with the Restore prompt open, and with the streak-ended modal open, in both modes.
- **Targets**: chip, Stats and Settings buttons 36 px below 400 px, 40 px from 400 px (accepted under WCAG 2.5.8, 24 px minimum met); tabs and toggle 36 px high; dialog buttons 44 px.
- **Focus order in the header**: title, chip, Stats, Settings, mode switch, (i), length picker, Give up, New game, keys.
