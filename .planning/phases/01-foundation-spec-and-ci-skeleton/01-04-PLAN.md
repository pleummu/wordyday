<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author -> GitHub Actions runner | Code from a PR runs on the CI runner with a GITHUB_TOKEN |
| GitHub Marketplace -> workflow | Third-party action code runs inside the job |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Elevation of privilege | GITHUB_TOKEN in ci.yml | mitigate | Top-level `permissions: contents: read`; acceptance check greps for it |
| T-01-10 | Elevation of privilege | fork PRs | mitigate | Trigger is `pull_request`, never `pull_request_target` (grep gate = 0) |
| T-01-11 | Tampering | third-party actions | mitigate | Only first-party `actions/checkout` and `actions/setup-node`, pinned to a major tag; SHA pinning reconsidered in Phase 8 |
| T-01-12 | Information disclosure | secrets in workflow | mitigate | No secrets used (grep `secrets.` = 0); no Vercel token in GitHub (D-14) |
| T-01-13 | Tampering | dependency install in CI | mitigate | `npm ci` against the committed package-lock.json |
</threat_model>
