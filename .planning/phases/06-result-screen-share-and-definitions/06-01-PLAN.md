## Phase Goal

**As a** player, **I want to** get a satisfying result screen when a game ends, with the answer, my stats, a definition and a way to share, **so that** I can replay, learn the word and show my result to friends.

(Derived from the ROADMAP Phase 6 goal "Users get a satisfying end-of-game screen where they can replay, learn the word and share the result", which is not in user-story form; same practice as Phase 5.)

<objective>
User story slice: **As a** player who just finished a game, **I want** a result modal to appear after the last row settles, showing whether I won, the word, my stats for this Board and Play again, **so that** the end of a game feels finished and I can go straight into the next one.

Purpose: delivers the core of RSLT-01 (D-01 modal half, D-02, D-03, D-04, D-06, D-20..D-23, D-30). The slim banner with "See result" (D-01 banner half, D-05, D-29, D-31) is 06-02.
Output: src/logic/timing.ts, the 'result' dialog with scheduled auto-open and input block in gameStore, StatsBlock (extracted from StatsModal), ResultModal, e2e/result.spec.ts.

Note for the executor: after this plan the modal auto-opens, so several legacy E2E specs (game, wordubado, tabs, storage, persistence, boards, streaks, forfeit, stats, restore, layout) that click the page after finishing a game will fail until 06-02 Task 3 migrates them. Do not edit them here; only run e2e/result.spec.ts. Unit tests (`npm test`) must be fully green at the end of this plan.
</objective>
