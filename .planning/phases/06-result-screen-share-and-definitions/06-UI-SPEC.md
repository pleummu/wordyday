# Phase 6 — UI Design Contract

> Visual and interaction contract for the Result modal, slim banner, definition area and Share. Extends `05-UI-SPEC.md`, `04-UI-SPEC.md`, `03-UI-SPEC.md` and `02-UI-SPEC.md` (tokens, typography, spacing, motion, accessibility, `Modal`, stat row and distribution chart all still apply); only deltas are specified here. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
> Sources: 06-CONTEXT.md D-01..D-31 (locked), current `src/styles/tokens.css`, `game.css`, `Modal.tsx`, `Banner.tsx`, `StatsModal.tsx`, `Toast.tsx`, `copy.ts`.
> Marking: `[LOCKED]` = fixed by SPEC or CONTEXT. `[DISCRETION]` = Claude's choice; the checker/owner may override.

## Scope

In scope: the Result modal (heading, answer, Show definition, compact stats, distribution, Share, Play again), the slimmed result banner with "See result", the definition area (loading, success for slang and dictionary, unavailable + Try again), Share feedback ("Copied" toast, "Copied ✓" button state, clipboard-failure fallback box), the win flourish, and the auto-open timing and input-block behaviour.

Out of scope: themes, the colour-blind toggle and palette (Phase 7; the share builder only takes a `colourBlind` flag), how-to-play, any change to tiles, keys, grid, header, Stats modal, Restore prompt or streak-break modal.

## Layout and Components

### Result modal (D-01, D-04, D-27, D-29) `[LOCKED structure]`

Built on the shared `Modal` (`dialog` name `result`; dismissable: close via Esc and backdrop; no close icon, consistent with the other modals; Play again is the visible way out). Card `min(360px, calc(100vw - 32px))`, padding 24 px, gap 16 px. Same Stats-modal rule: `dialog.modal:has(.result-panel)` gets `max-height: calc(100dvh - 32px)` and its `.modal-card` `overflow-y: auto` (never horizontal scroll). At `max-height: 540px`: card padding `var(--space-3)` and gap `var(--space-2)` so more fits before it scrolls.

```
You got it in 4/6!                 <- Heading h2 (+ 32x4 sage bar beneath, wins only)
CRANE                              <- answer, Heading, letter-spaced
[        Show definition        ]  <- full-width secondary button (or the definition panel)
 12      83%      4        9       <- stat row (Played, Win %, Streak, Best)
Played  Win %  Streak   Best
Guess distribution                 <- Label h3
1 ▌ 0
2 ▌▌ 3
3 ██████ 10                        <- bars, just-won row sage
...
[   Share   ] [  Play again  ]     <- two equal buttons, one row
```

| Part | Spec |
|------|------|
| Heading (`id` = titleId) | Win: "You got it in {n}/{max}!" Loss: "Out of guesses". Give Up: "You gave up". `<h2 class="modal-heading result-heading" data-result="won|lost|gave-up">`. Left aligned (modal pattern) |
| Win accent bar `[DISCRETION]` | `::after` on the win heading only: 32 x 4 px, `--color-accent`, `--radius-pill`, `margin-top: var(--space-2)`. Static, present under reduced motion too |
| Answer (`id` = bodyId, used as `aria-describedby`) | `<p class="result-answer">` containing a visually hidden prefix "The word was " then the word. Same on win, loss and Give Up. Margin 0 |
| Show definition | Full-width (`width: 100%`) secondary `.modal-button`, height 44. Replaced in place by the definition panel once clicked (see Definition area). Hidden until clicked in both Modes `[LOCKED R-RESULT-2]` |
| Stats (D-04) | Reuse the `.stat-row` (4 cells: Played, Win %, Streak, Best) and the `.dist` chart with the same Label/Heading styles, empty-state ("—") rules and accessible suffixes as the Stats modal. This Board only: no mode toggle, no length tabs, no "Gave up" line, no "Avg guesses", no Day Streak/Restores footer. Chart heading "Guess distribution" (h3, `.modal-subheading`). Chart rows: 1-5 (4 letters), 1-6 (5), 1-7 (6). The just-won row is highlighted (sage) only after a win; after a loss or Give Up nothing is highlighted. If the Board has no wins (e.g. first game is a loss) the chart region is replaced by the existing one-line empty state "No wins yet. Go play one!" |
| Win Streak reset (D-05) `[DISCRETION]` | No visible reset word. The Streak cell shows the new number (0 after a loss or Give Up). When the previous Win Streak was above 0 the cell's visually hidden text becomes "Current win streak 0, reset" so screen-reader users still hear the reset that the banner line used to announce. Win: "Current win streak {n}" |
| Actions | One row, `justify-content: stretch`, `gap: var(--space-2)`. DOM and visual order: **Share** (secondary), **Play again** (primary, `data-initial-focus`). Both `flex: 1 1 0; min-width: 0` so the row stays a single line at 320 px (each button about 116 px in a 240 px content width) instead of the generic `column-reverse` stack below 400 px (override for this modal only) |
| No emoji preview (D-27) | Nothing else in the modal; the real grid is behind it |

Vertical budget at 320 x 500 (viewport 500, dialog max-height 468): heading 24 (+12 with win bar) + answer 24 + Show definition 44 + stat row 56 + chart heading 17 + chart (5 letters: 6 rows = 140) + actions 44 = 349 (361 with bar) plus 6 gaps x 8 or 16 and padding 32 to 48. At 540 px and below that is about 349 + 48 + 32 = 429 to 441 inside 468, so a 5-letter win usually fits; a 6-letter board (7 rows, 164) or an opened definition panel (about 80 to 120 px) overflows and the card scrolls inside the dialog (same pattern as Stats). The page itself never scrolls; Play again is reached by Tab (focus scrolls into view; it receives initial focus on open, so it is visible at open time).

### Definition area (D-07..D-11, D-24..D-26)

Sits where the Show definition button is. After the click, the button is removed and a panel takes its place:

```
<div class="definition" role="region" aria-label="Definition" aria-live="polite" tabindex="-1">
```

Panel: `--color-surface` fill, radius 14, padding `var(--space-2) var(--space-3)`, internal gap `var(--space-1)`. On reveal, focus moves to the panel (`tabindex="-1"`) so keyboard focus is not lost when the button unmounts; the live region announces the loading text and then the result. When the modal is reopened with the definition already revealed (D-24), the panel is rendered open with no focus move and no lookup (cached) and the open modal still focuses Play again (D-30).

| State | Content |
|-------|---------|
| Loading | One Label line "Looking it up..." (static text, no spinner and no animation, so nothing changes under reduced motion). `aria-busy="true"` on the panel. Aborts after 5 s (D-10) |
| Slang (curated; Wordubado + word in that length's reviewed slang list; D-08, D-11) | One Body 16/400 line: the curated definition (max 69 characters, so at most two lines on a phone). No POS label, no credit line, no network call. The `crude` flag changes nothing |
| Dictionary success (D-09) | Up to 2 rows (`<dl>`), each a two-column grid `grid-template-columns: 5.5em 1fr; column-gap: var(--space-2)`: POS (`<dt>`, Label 14/600, left aligned, lower case as returned, e.g. "noun") and sense (`<dd>`, Body 16/400). Sense text is cut at 100 characters at a word boundary with "…" (the full text is not shown; this keeps the panel short on a phone). Below the rows, right aligned (`text-align: end`): "Source: dictionaryapi.dev" Label-regular 14/400. The credit is plain text, not a link |
| Unavailable (offline, 404, timeout 5 s, network error, bad response shape; D-10) | Label 14/600 line "Definition unavailable" and, beneath it, a **Try again** secondary pill (height 36, min-width 96, left aligned). Retry returns to Loading and moves focus to the panel (not left on a removed button). No error colour; this is not alarming |

- Failed lookups are not cached; reopening the modal with the area revealed retries automatically (D-26). Only successes are cached per word for the session (D-24). Play again, reload and Board switch hide the area again (D-25).
- The panel never contains the answer word again (it is already above).
- Dictionary rows with no usable POS or sense are skipped; zero usable rows counts as an unexpected shape and shows "Definition unavailable".

### Share (D-12..D-19, D-27, D-28)

Share builds the text from a pure function (inputs: mode, length, submitted row states, attempts used, max attempts, outcome, `colourBlind`, origin).

```
Wordle 5 - 4/6                      <- Normal
Unlimited Wordle - Wordubado 5 - 4/6   <- Wordubado
<blank line>
🟨⬜⬜⬜⬜
⬜🟩⬜🟨⬜
...
<blank line>
https://<window.location.origin>
```

| Rule | Spec |
|------|------|
| Header | Normal `Wordle {length} - {n}/{max}`; Wordubado `Unlimited Wordle - Wordubado {length} - {n}/{max}`. A loss and a Give Up use `X/{max}` instead of `{n}/{max}` (D-13) `[LOCKED]` |
| Grid | Only the submitted rows, one line per row, no letters. Normal: 🟩 correct, 🟨 present, ⬜ absent. Colour-blind (flag true): 🟧 correct, 🟦 present, ⬜ absent. **No dark-theme square variant this phase** `[DISCRETION]`: ⬜ is used in every theme (themes are Phase 7, which may add a ⬛ option through the same builder) |
| URL line | `window.location.origin` on its own last line |
| Device test (D-17) `[DISCRETION]` | Use the share sheet only when `navigator.share` exists AND the primary pointer is coarse (`matchMedia('(pointer: coarse)').matches`) AND `navigator.maxTouchPoints > 0` (the last clause also catches iPadOS that reports as desktop Safari with a touch screen, where `(pointer: coarse)` is true). Otherwise copy |
| Handler | `navigator.share(...)` and `navigator.clipboard.writeText(...)` are called synchronously in the click handler (user activation). The grid text is built before the click and cached; no `await` before the call |
| Share-sheet result | Resolves: nothing visible changes (no toast, no button change). Rejects with `AbortError`: nothing happens (D-18). Any other rejection: fall back to the clipboard path |
| Clipboard success (D-28) | Toast "Copied" (info kind, default 1860 ms). The Share button's visible label swaps to "Copied ✓" for 2000 ms then returns to "Share". The button keeps `aria-label="Share"` throughout and the swapped label is inside an `aria-hidden` span, so the only screen-reader announcement is the toast's `role="status"` (announced once, not twice). Button width does not change (fixed by flex 1) |
| Clipboard failure (D-19) | Insert, directly under the actions row, a note and a read-only textarea: note "Couldn't copy. Select the text and copy it." (Label-regular 14/400), then `<textarea readonly rows="4" aria-label="Share text">` containing the share text, selected (`select()`) and focused. The Share button stays and can be pressed again. The fallback is removed when the modal closes or the player presses Play again. Added content makes the card scroll if needed; the textarea is scrolled into view |
| Banner | No Share button (D-29) |

### Slim result banner (D-01, D-05, D-29)

Replaces the Phase 4/5 banner contents inside the same `.banner` box (same `min-height: var(--controls-h)`, same surface fill, same loss/Give Up `--color-error` border). The `banner-streak` line and `data-streak` padding rule are removed (the Win Streak lives in the modal).

| Outcome | Heading (Heading 20/600) | Body (Label 14/600) |
|---------|--------------------------|---------------------|
| Win | Solved in {n} | none |
| Loss | The word was {ANSWER} | none |
| Give Up | You gave up | The word was {ANSWER} |

Below the text, one row of two pills, `gap: var(--space-2)`, `flex: 1 1 0; min-width: 0; max-width: 140px`, height 44 (36 at `max-height: 540px`): **See result** (neutral, `--color-bg` fill, 1px `--tile-filled-border`) then **Play again** (sage primary, existing `.play-again`; its `min-width: 128px` is lowered to 0 inside the banner row so two buttons fit 256 px at 320 px).

Banner height proof: padding `var(--space-3)` x 2 = 32 + heading 24 + gap 8 + buttons 44 = 108 px (Give Up adds 17 + 8 = 133 px) inside `--controls-h` 148. At `max-height: 540px`: padding 8 x 2 + 24 + 8 + 36 = 84 px (Give Up 109 px) inside 124. `.banner` keeps `min-height: var(--controls-h)` and must not grow beyond it.

- The banner no longer has `aria-live`: the Result modal's own dialog semantics announce the result on open, and the banner would otherwise announce a second time. A finished game restored on load shows the banner silently (unchanged Phase 4 rule).
- The "autoFocus on mount" logic is removed; focus is managed by the modal (below).

## Interaction Rules

### When the modal opens (D-02, D-03, D-20, D-21, D-23) `[tunable]`

| Event | Trigger | Delay |
|-------|---------|-------|
| Win | `finishReveal` | wait for the row bounce to end plus 400 ms: `BOUNCE_MS(length) + 400`, where `BOUNCE_MS(length) = 400 + (length - 1) x 100` (matches the `.row[data-bounce]` keyframes: 800 ms at length 5, so the modal opens 1200 ms after reveal end; 1000 ms at length 4, 1400 ms at length 6) |
| Loss | `finishReveal` | 600 ms |
| Give Up | the confirm's "Give up" button | opens right after the confirm closes (about 120 ms, the existing close animation); no extra pause |
| Reduced motion (win and loss) | `finishReveal` | 300 ms (the bounce is removed by the reduced-motion rules and the reveal is shortened) |

- All values live as named constants next to `revealDurationMs` in `gameStore.ts` and are derived from the same duration source/reduced-motion flag, so E2E can compute them rather than hard-code waits.
- **Input block (D-21):** from reveal end until the modal opens, `isInputBlocked` stays true: no typing, no Board/Mode/length switch, no opening of Stats or Settings (the same `disabled` styling as the Phase 5 "revealing" state; the pause is treated as part of `revealing`). The modal always opens on the Board that finished.
- **Priority (D-03) `[DISCRETION]`:** if the Restore prompt or the streak-break modal is open or pending at the moment the delay elapses, the Result modal is **skipped, not queued** (no surprise dialog appears after the player answers). The banner "See result" button reaches it at any time. Any other open dialog is not a conflict because input is blocked during the pause.
- The Day Streak toast keeps firing at reveal end as today and is still on screen (1860 ms) when a win's modal opens only at the very edge; it must be visible above the modal when it overlaps (see Toasts).
- **Auto-open only after finishing in this session (D-02).** A Board switch, reload or other-tab sync to a finished Board shows the banner only.

### Focus (D-30, D-31)

- Opening the modal (auto or via See result) focuses **Play again** (`data-initial-focus`).
- **Held-Enter guard:** the Result modal ignores `keydown` Enter/Space events with `e.repeat === true` on its buttons (call `preventDefault` in a capture listener on the dialog), so a held Enter from the final submit cannot trigger Play again.
- Closing the modal with Esc, backdrop click or after Play again: focus returns to the banner "See result" button (via `fallbackFocus`, since the opener at auto-open time is the body). After Play again, focus goes to the page body so physical-keyboard play resumes (same as the banner's Play again).
- The Modal's Tab trap cycles Share and Play again (and Show definition / Try again / the textarea when present); the definition panel is only focusable programmatically.
- With the modal closed on a finished Board, letters and Enter do nothing (D-31). Enter on a focused banner button presses it (`data-own-enter` on both).
- Opening the modal with "See result" does not change any state; it can be reopened any number of times.

### Play again (D-06)

The modal's Play again and the banner's Play again run the same action. The modal closes, the next game starts on that Board, and the definition-revealed state, the copy-fallback box and the "Copied ✓" label are reset.

### Toasts (D-05, D-28)

The existing `Toast` is a fixed layer in the page, which sits **underneath** a modal `<dialog>` (top layer). Required change: render the toast layer as a manual popover (`popover="manual"`, shown with `showPopover()` while a toast is active) and re-show it after any dialog opens, so it is in the top layer above the dialog. Fallback if the implementer prefers: render the active toast inside the open dialog. Either way: toast text, kind, 1860 ms life, one-at-a-time, position and `role="status"` are unchanged. New toast copy: "Copied".

## Accessibility (additions)

- **Result modal:** native `<dialog>` via `Modal`; `aria-labelledby` the outcome heading, `aria-describedby` the answer line ("The word was CRANE"). On auto-open the dialog name and description are announced; the banner is silent (no `aria-live`).
- **Definition area:** `role="region"` named "Definition", `aria-live="polite"`, `aria-busy` while loading. Loading, success and unavailable text are all plain text (never colour-only or icon-only). Focus moves to the panel on reveal and after Try again.
- **Share:** accessible name stays "Share" across the copied state; "Copied" is announced once by the toast status region (D-28). Share-sheet path announces nothing extra. The textarea fallback has `aria-label="Share text"` and the note is adjacent plain text (`aria-describedby` on the textarea pointing at the note).
- **Stats inside the modal:** same hidden-suffix accessible phrases as the Stats modal; chart rows say "{n} guesses: {count} wins" and append ", latest win" for the highlighted row.
- **Targets:** modal primary and secondary buttons 44 px; Try again 36 px; banner buttons 44 px (36 px at `max-height: 540px`, matching the key height).
- **Contrast:** all text is `--color-text` on `--color-bg` (about 13:1) or `--color-surface` (about 11:1). "See result" uses `--tile-filled-border` (`#a8a59c`) as a 1px border on `#fbfaf7`: about 2.3:1, below the 3:1 non-text guideline, so it is not the only cue; the button is identified by its text label and fill difference against the banner surface, which is acceptable for a labelled control. If the checker flags it, darken the border to `--color-muted` (about 3.8:1). Run axe with the Result modal open (win, loss, Give Up; definition revealed in each of loading/success/unavailable; fallback box shown).
- **Keyboard-only flow:** finish a game, wait for the modal, Enter starts the next game (after the Enter-repeat guard), or Tab to Share/Show definition. Esc closes and focus lands on See result.
